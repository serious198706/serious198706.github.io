## ⚡ Google 开源 AX：为 Agent 时代构建的原生编排系统

Google 今日低调开源了 **AX（Agent Open Orchestrator）**，一个从 DeepMind 的 Agent 运行时研究诞生、专为 Agent 工作负载设计的声明式控制平面。AX 建立在 Agent Substrate 之上，提供四大原语：**Task**（沙箱化隔离执行）、**Workspace**（Git 仓库 + MCP 服务器 + 技能自动编排）、**Gateway**（网络策略与凭据注入）、**Model**（模型配置与密钥管理）。

其核心洞察在于：Agent 不是微服务，也不是批处理作业——它们是**有状态、突发性、长生命周期的 Actor**，密集计算一分钟，然后在等待模型响应或人工审批时闲置数十分钟。传统编排器在此场景下成本失控，而 AX 通过亚秒级挂起/恢复实现了极高的集群密度。

> "Agents are a new kind of workload. They accumulate state, need strict isolation, call out to model APIs and tool servers, and can burn money in a loop if nobody is watching."

AX 的声明式 API（`task.yaml`）允许你直接用自然语言描述目标环境——"Set up a Python 3 development environment"——由运行时内的 Agent 自动完成配置。这意味着基础设施本身在变成**生成式的**：你描述状态，系统自行抵达。这是 K8s 之后最激进的云原生抽象。

**这对生态意味着什么？** Google 在 Agent 基础设施层的开源举措，实际上是在定义 Agent 时代的编排标准。在 LLM 趋于商品化的背景下，谁能定义 Agent 的执行与交互模型，谁就掌握了下一轮平台话语权。

## 🕵️ OpenAI 的秘密追踪：当 ChatGPT 知道你在其他网站做了什么

一篇技术深度调查揭示了一个令人不安的现实：**OpenAI 正在通过一套名为「Bazaar」（集市）的广告基础设施，将 ChatGPT 用户与跨站浏览行为绑定。** 这也许是今年以来最具冲击力的 AI 隐私新闻。

机制并不新鲜——Meta 和 Google 用同样方案做了二十年——但套在 AI 聊天产品上，意义完全不同。

核心流程：当你访问 ChatGPT 时，客户端生成 16 字节随机标识符，通过 `/backend-api/bazaar/obi/sync-token` 获取一个 RS256 JWT，然后跨站 POST 到 `bzr.openai.com/v1/obi/sync`，设置一个 **SameSite=None、有效期一年**的 cookie `__obi`，作用域为 `.openai.com`。

当你在 Chewy、Wayfair、Coursera 等网站浏览时，这些站点加载的 OpenAI 广告 SDK（一个简单的 `<script src>` 标签）会自动携带 `__obi` 发送到 OpenAI。SDK 还会从页面中抓取邮箱、电话、姓名、地区等信息（通过替换 `window.dataLayer.push` 拦截 GTM 数据总线），SHA-256 哈希后上传。

> "On my device, one __obi value was sent to OpenAI from 12 commercial websites under 13 distinct pixel IDs, including Chewy, Wayfair, ThriftBooks, Eventbrite, HelloFresh, Coursera and SeatGeek."

更值得关注的是：**即便用户选择「仅允许分析型 cookie、拒绝营销型 cookie」，这个机制仍然运作。** OpenAI 的 Cookie 政策将 `__obi` 归类为「分析型」，但它的实际行为是跨站追踪与身份关联。作者向 OpenAI 发问，得到的回应只是「会内部审查」。

**这三件事叠加产生了独特的危险性：**
1. 人们在 ChatGPT 上说了不会对社交网络说的话（医疗咨询、债务解决方案、诉讼准备……）
2. OpenAI SDK 从页面抓取的内容包括医疗词条、债务方案路径和法律咨询表格
3. Agent 正在代表用户执行越来越多的操作——如果追踪数据泄露，攻击面远超传统广告网络

这不仅仅是隐私问题，而是 **Agent 时代的信任基础设施问题**。当 AI 代理可以替我们购物、发邮件、填表格时，谁在后台看着代理们的一举一动？

## 🧲 Pirate Face：用 BitTorrent 让 AI 模型永远不死

如果说 OpenAI 代表的是集中化与商业化的 AI，**Pirate Face** 则站在光谱的另一端。这个平台做的事情非常直接：**将 Hugging Face 上的开放模型转化为 BitTorrent 磁力链接，由 P2P 网络永久承载。**

当某个模型在 Hugging Face 上被删除时（作者、监管者或平台自身的意志都可能触发删除），Pirate Face 上的种子仍然存活——只要有一个人在做种。每个文件都携带官方的 SHA-256 校验和，确保你下载的权重与 Hugging Face 上的原始文件逐比特一致。

> "Every model is a torrent that also downloads straight from Hugging Face. The day it's gone, the swarm keeps it alive — there's no single host to shut down."

当前已有超过 66.9 万个模型被索引为种子，覆盖 Qwen、DeepSeek、Llama 等主流开源系列。平台还提供了一个 Drop-in API，只需设置 `HF_ENDPOINT=https://pirateface.co`，现有管道即可零代码切换。

这在政治上极其重要：当各国政府对 AI 模型的监管日益严格（出口管制、内容审查、许可证撤销），**P2P 分发是一种无许可的抗审查基础设施**。模型权重不是言论，但它承载着言论的能力——Pirate Face 正在为「主权 AI」搭建物理层。

## ✍️ 如何与 LLM 共同写作——而不失去你的声音

Thomas Ptacek（知名安全研究员）写了一篇关于 LLM 辅助写作的实操指南，在 HN 上引发高质量讨论。其核心论点非常清晰：**把 LLM 当 copyeditor，别当 ghostwriter。**

两条铁律：

**规则一：不允许使用 LLM 建议的任何单个词语。**
理由：前沿模型在措辞选择上过于完美——它们输出的每一句都是杂志头条级别的表达。一篇文章里出现几十个「头条句」会产生诡异的 uncanny valley 效应，读者会本能地感知到「这不是人写的」。

> "Frontier models are wedged in a mode where everything they write is a magazine headline. Headlines are good, but you'd wonder about someone who wrote an article with dozens of them."

**规则二：避免鼓励。**
LLM 对你任何初稿的回复都是「太棒了！」，但这正是你最不需要听到的——初稿大部分段落都很差、逻辑混乱、至少多写了 750 个字。模型的鼓励会让你加倍坚持第一稿的冲动，而正常写作过程中你会重新思考、替换段落——这些「重思」过程正是你声音的承重墙。

> "Those rethinks are load-bearing parts of your voice. Readers won't put their fingers on what's wrong, but they'll sense that you've become artificially-flavored."

Ptacek 建议的实操流程：自己写完 → 让 LLM 标记问题（被动语态、过度使用某个词、段落可移动性）→ 针对每个问题自行重写 → 让另一个没有上下文的模型评判哪个版本更好。他还推荐了《Style: Lessons In Clarity And Grace》这本书，称之为「把 copyediting 变成 Java 编码」的神书。

**这对行业的启示：** 当 AI 写作工具越来越强大，真正稀缺的不是生成能力，而是**判断力**——知道什么时候该听模型的建议，什么时候该坚信自己的判断。Ptacek 的方法论本质上是一种元认知技巧：利用 AI 的盲点来保护自己写作的独特性。

## 🧠 33 毫秒的非自回归决策模型：Laya 的故事

当所有人都在追逐更大、更长的自回归 LLM 时，**Laya** 选择了相反的方向：一个纯粹的非自回归决策引擎，面向 ChatGP 的判断任务而非生成任务。

它的核心洞察极其简洁：**在大多数 AI 管道中，生成式 LLM 被用在了纯粹反射性判断上**——邮件是哪个部门的？这是钓鱼吗？这个 prompt 在尝试越狱吗？——为此等待 500ms-2000ms 的 token 流生成、支付昂贵的推理费用、再用正则从自由文本解析标签，完全是杀鸡用牛刀。

> "When an LLM outputs 'confidence: 0.95', it is just predicting tokens that sound confident. There is zero mathematical calibration behind it."

Laya 基于双向编码器（ModernBERT/mmBERT），在单个 GPU 上只需 **32.8 毫秒**就能完成一次判断，同时输出经过校准的概率分布。它永远不会产生幻觉——因为它根本不生成文本，输出空间只有概率和数字。

更值得关注的是这篇报道的**叙事本身**。作者声称自己早在 2025 年 3 月就发表了 arXiv 论文，随后一年中一个资金充足的「前沿实验室」（TypeSafe AI，由 ChatGPT 共同发明人创立）推出了一款名为 Jev 的产品，提出了完全相同的概念，却「像全新的科学突破一样」宣布，且未开源任何训练数据或权重。这揭示了一个 AI 行业的系统性问题：**学术独立研究者与资金充裕的实验室之间的信息不对称正在加剧**。

Laya 完全开源（Apache 2.0），支持 100+ 语言，速度比 Jev 快 6-8 倍。如果你正在做 agent 可观测性、客服路由、安全检测一类的工作，这可能是比调用 GPT-5 更合理的选择。

## 🔮 幸存者 ML 模型：数据科学版的「权力的游戏」

最后一篇值得关注的 AI 文章比较轻松——但蕴含的方法论很有趣。一位数据科学家用逻辑回归构建了预测真人秀《幸存者》获胜者的模型，在 HN 上获得 500+ 点赞。

关键是**特征工程**：
- **危险次数**（在部落会议上收到任何投票的次数）
- **忏悔片段占比**（过去 3 集剪辑中的 confessional 份额——这代表了「编辑的叙事权重」）
- **年龄**（最佳胜率在 30 岁左右，U 型曲线）
- **参赛次数**、**是否持有优势**

有趣发现：获胜模型和淘汰模型保留的特征完全不同——这意味着**「防止被淘汰」和「最终获胜」是两个不同维度的事**。你在游戏中活得久不代表你赢得陪审团的支持。Rob Cesternino 在播客中也得出类似结论："a low likelihood of elimination doesn't necessarily give you high odds of winning."

模型比随机猜准确 2 倍（约 20%），对于真人秀这种充满随机变量的场景，这个结果已经相当可敬。

**这对 AI 从业者的启发：** 作者展示了**小数据 + 逻辑回归 + 深思熟虑的特征工程**仍然可以产生有意义的预测——当领域知识足够深时，复杂模型往往不是必要的。对于大部分结构化预测任务，线性模型的解释能力和稳健性仍然难以被黑盒模型取代。
