千禧年难题与"先行者争议"：OpenAI 的 Navier-Stokes 解法暗含的伦理红线 链接到标题

这是本周最炸裂的进展，也是最复杂的伦理难题。OpenAI 宣布其内部 AI 系统（基于 GPT-6 Astra）解决了 Navier-Stokes 方程的存在性与光滑性问题——这是克雷数学研究所七个千禧年大奖难题之一，奖金 100 万美元。整个过程：100 个 AI agent 协同工作约 50 小时，生成了 166 页的证明，随后在 Lean 4 定理证明器中以 17 小时完成形式化验证。

但是，争议随之而来。Quanta Magazine 的深度报道揭示了一个关键的伦理学问题：OpenAI 的研究人员承认，他们是在听到传闻——Anthropic 员工 Levent Alpöge 和 NYU 教授 Tristan Buckmaster 已经接近解决 Navier-Stokes 问题——之后才启动的这个项目。OpenAI 的 AI agent 在解决过程中，据称可能获取并受益于 Buckmaster 和 Alpöge 尚未发表的成果。

各方对当时交流的细节给出了不同版本的说法。Buckmaster 似乎暗示 OpenAI 的研究人员或 AI agent 可能访问了他们的工作。

John D. Cook 在他的博客中则选择聚焦另一个几乎无人讨论的侧面：Lean 4 形式化验证的降本意义。他指出，2005 年的行业估计是一页本科教科书需要一周时间（40 小时）形式化，而研究论文难度约为教科书的 20 倍。按此计算，166 页论文需要约 132,800 人工小时。OpenAI 的 AI 只用了 17 小时——将成本降低了四个数量级。

“将任何东西的成本降低四个数量级，就是革命性的。” — John D. Cook

但评论区中有读者指出，OpenAI 为此花费了约 100-200 万美元的计算资源，约合 10,000 数学家小时的价值——技术成本在下降，计算成本的账需要更精细地算。更深层的是，形式验证回答的是"我是否实现了写下的内容"，而不是"我是否写下了正确的东西"——规范鸿沟（specification gap）仍然需要昂贵的人类劳动。

OpenAI Agents API：Codex 从代码助手进化为云 agent 平台 链接到标题

9 月 10 日，OpenAI 正式发布了 Agents API（公开测试版），让开发者能够用 Codex harness 在 OpenAI 完全托管的云环境中构建和运行 agent。这实际上是 OpenAI 在 8 月 AgentKit 之后的又一布局——将 agent 从 SDK 层面的工具包升级为云原生托管服务。

Agents API 允许开发者将 agent 部署为长期运行的云进程，具有 Codex 的自动规划、执行、测试和交付能力。

到 2026 年 6 月，重度 Codex 用户的日均 agent 运行时间已超过 60 小时。而 Assistants API 已在 8 月 26 日关闭。OpenAI 正以 All-in 的姿态押注 agent 基础设施。发布会上 OpenAI 同时预告了 9 月 29 日 DevDay 上的 Managed Agents 功能——直接将 agent 管理体验对标 Anthropic 的当前方案，目标指向企业级客户。

Cognition SWE-2：用 Pareto 最优挑战前端闭源模型 链接到标题

Cognition 的 SWE-2 则以另一种方式演绎了"agent 能力升级"。基于 Kimi K3（2.8T 参数）后训练，SWE-2 在 FrontierCode 1.1 Main 上达到 50.0%（Fable 5.1 为 50.9%，GPT-6 Astra 为 53.3%），但成本降低了 64%。在 Terminal-Bench 2.1 上甚至以 92.8% 超过了 Fable 5.1 的 91.4% 和 GPT-6 Astra 的 89.9%。

SWE-2 的技术报告中有几个值得行业学习的设计决策：

  1. 单次 RL 训练覆盖所有推理力度（effort levels）：不再为"中/高/最大"分别训练专家，而是通过 Pareto 切线定价的 λ 参数，在单一 RL 过程中同时优化整个成本-性能前沿面。
  2. 长度加权奖励基线：利用梯度范数与 rollout 长度的强相关性，实现零额外成本的方差削减——显著稳定了训练过程中的 KL 散度。
  3. 实际行为改进：medium 模式下首次编辑的中位数从 48 步降到 18 步；模型学会了"只探索需要探索的部分"。

“更强的工程判断力让 agent 能写出更完整的解决方案，同时减少不必要的绕路和冗余阅读。” — Cognition 团队

SWE-2 的一个重要隐含信息是：闭源模型（Fable、GPT-6）的领先优势在编码领域正在收窄。虽然闭源模型仍保持少量领先，但性价比差距让开源/半开源模型在真实场景中更具吸引力。这与 Magic 的 pretraining 论文传达的信号一致——算法效率正在以超越硬件规模化的速度进步。

用少得多的计算做更多的事：Magic 的 >10x 效率突破 链接到标题

Magic 时隔近两年发布了一篇爆炸性的预训练技术报告：其预训练配方的计算效率已比主流开源基础模型高出 10 倍以上。这对于"预训练是大厂游戏"的主流叙事是一个直接挑战。

“我们没有 10 万张芯片，所以只有一条路可走：算法效率。” — Magic 团队

Magic 可能是全球训练万亿参数模型的最小团队（整个团队的核心人员不到两位数），其报告暗示：智能的门槛不在硬件，而在判断力。这句话的言下之意是——在后 scaling law 时代，找到正确的计算分配策略比堆更多 GPU 更重要。

这与 SWE-2 在 post-training 层面的效率突破形成了有趣的呼应：推理层面的效率（SWE-2 的 Pareto RL）和训练层面的效率（Magic 的 >10x 加速）正在同时逼近各自的成本-性能最优边界。

精细视觉的开放路径：MultiMatte 的可提示背景移除 链接到标题

Feyn 推出的 MultiMatte 是一个相对低调但有意思的发布。它不是传统的"背景移除"——所有这类模型都会尝试移除背景——而是让你用文字指定要保留的对象，然后只移除其他内容。

技术方案的巧妙之处在于解决了 SAM（Segment Anything）系列的软边缘问题。SAM3 虽然是概念可提示检测器，但生成的二进制掩码对半透明对象和精细边缘（如头发、模糊屏幕）处理不佳。MultiMatte 通过改进的 matting 方法，在这类场景中实现了更好的边界保真度。

“因为蒙版永远不会是空的，所以即使提示图像中不存在的东西，模型仍然会返回一个结果。读取 presence_logits 可以判断区别。” — Feyn 团队

这不是一个改变行业的发布，但它代表了一种趋势：AI 视觉的"指令式编辑"正在从文字到图像生成向图像理解+编辑的方向扩展。MultiMatte 配合 SAM3、FeyNobg 构成了一个开放的全栈背景处理工具链。
