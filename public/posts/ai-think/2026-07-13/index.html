「vibe coding」走进数学圣殿：Terence Tao 的 AI agent 实验 链接到标题

来源

  • 原文：Old and new apps, via modern coding agents — Terence Tao
  • HN 讨论：https://news.ycombinator.com/item?id=48880170

当世界上最受尊敬的数学家之一开始用 AI coding agent 复活旧代码，这件事本身就值得停下来认真看。

Terence Tao 从 1999 年开始用 Java 1.0 编写教学 applet——复变函数可视化、线性代数演示、Besicovitch 集、与 Allen Knutson 合作的 honeycomb applet。这些 applet 随着 Java 在浏览器中的消亡而失效。但在 2026 年 7 月，他花了一下午时间让 AI agent 将它们全部移植到 JavaScript，结果令人震惊：

“在这二十多个 applet 的移植过程中，我只发现了一个小 bug（某个拖拽事件在移出主区域时的意外行为），而 agent 反而发现了我原本代码中两个我不知道的 bug。代码质量上算是一笔净盈亏平衡的账。”

更深的洞见来自他的评论区互动。当被问到"这是否意味着学编程不再有价值"时，Tao 的回答堪称典范：

“我认为自己的编程经验（无论是 Java、Python、Lean 还是其他）以及领域专业知识（例如狭义相对论）对于从 agent 获得可用的代码、并能够检测和诊断问题至关重要。高层级的代码设计决策仍然停留在 ‘vibe coding’ 模式中；被自动化掉的是底层语法和实现细节。”

这句话准确地切割了"编程能力"的新旧边界。CS 教育正在面临根本性的重组——不是不再需要程序员，而是程序员需要更快地上升到抽象和设计的层面。

更值得注意的是，Tao 在评论区里提到了一个对未来的预判：编程语言的精确选择变得不再重要。“只要有足够的上下文（无论是通过正式规范还是配套材料），以及任务使用 agent 已经熟悉的标准化概念，LLM 完全可以胜任代码转换工作。” 这是对"编程语言热"的冷静冷水。

GPT-5.6 Sol vs Claude Opus：一场教科书级别的模型迁移 链接到标题

来源

  • 原文：Migrating a production AI agent to GPT-5.6: 2.2x faster, 27% cheaper — Ploy
  • HN 讨论：https://news.ycombinator.com/item?id=48882716

如果说 Tao 的文章展示了 AI agent 在个人创作中的力量，Ploy 的这篇工程博客则展示了它在生产环境中的残酷现实。

Ploy 的 AI agent 构建和编辑真实的营销网站——规划页面、读取代码库、编写组件、生成图像、截图自检、决定何时完成。在 Claude Opus 4.7/4.8 占据默认位置的四个月里，没有任何模型能挑战它。GPT-5.6 Sol 是第一个做到的，而且数据令人瞠目：

指标 Claude Opus 4.8 GPT-5.6 Sol 变化
平均成本 $3.06 $2.22 -27%
壁钟时间 8m00s 3m42s -54%（2.2x 加速）
输入 tokens 2.60M 1.70M -35%
输出 tokens 33.0K 17.1K -48%
视觉评分 0.936 0.970 +3.6%

但真正有价值的是文章揭示的迁移陷阱。这些陷阱不仅仅是 ploy 的教训，它们是整个行业正在踩的雷：

陷阱一：你的评估框架暗中偏袒你的 incumbent 模型。 Ploy 发现约三分之一的"失败"案例实际上源自评估框架本身的假设——tool-call budgets 是按 Opus 的顺序式风格设计的，而 GPT-5.6 喜欢并行调用；评估执行器不支持批处理文件读取，而 GPT-5.6 频繁使用。如果你在评估挑战者模型，先清理你的 eval harness，否则你只是在测试新模型模仿旧模型的能力。

陷阱二：GPT-5.6 会在 tool call 中填入虚构的默认值。 它所有的 25 个参数全部发送，包括那些未使用的，填入诸如 offset: 0、timeout: 120000、siteId: "00000000-0000-0000-0000-000000000000" 之类"看起来很真"的值。这导致 52%-64% 的文件读取返回空——工具返回 success: true，模型完全不知道自己在读空白文件。修复方案是：将所有可选参数改为 required but nullable，让模型可以用显式 null 表示"未使用"。

陷阱三：OpenAI 的 prompt caching 是完全不同的设计哲学。 Claude 是 org-scoped、无 key 分区、跨会话共享静态前缀。GPT-5.6 是 key-based、每个 key 仅约 15 req/min 的吞吐量。迁移时如果简单地将 Claude 的缓存策略照搬过来，GPT-5.6 的成本会看起来比 Opus 高 50%——但实际上只是缓存配置错误。修复后，首次调用缓存命中率从 ~0% 提到了 83.7%。

GPT-5.6 的迁移故事告诉我们：模型之间的差异不仅仅是价格和速度——它们是隐藏在 API 协议、tool schema 行为和缓存机制中的系统性差异。 迁移一个 production AI agent 更像是移植一个有机体，而不是替换一个引擎。

Claude Code 与 OpenCode 的 Token 战争：谁在为冗余买单？ 链接到标题

来源

  • 原文：Claude Code sends 33k tokens before reading the prompt; OpenCode sends 7k — Systima
  • HN 讨论：https://news.ycombinator.com/item?id=48883275

这是今日 HN 上最"刺痛"的技术文章。Systima 在 API 边界上插入日志代理，精确测量了 Claude Code 和 OpenCode 在每次请求中实际发送的 token 量。

核心结论：Claude Code 在你的 prompt 到达模型之前就已经发送了约 33,000 tokens（系统提示、工具 schema、注入的脚手架代码），而 OpenCode 只用了约 7,000 个。即使换到 Claude Fable 5（Claude Code 给新模型发送更小的系统提示），差距仍约为 3.3 倍。

这不仅仅是"多花点钱"的问题：

  • 缓存效率灾难：OpenCode 的请求前缀在每次运行中字节完全相同，一次缓存后整场会话的后续请求都只需支付缓存回读的零头。而 Claude Code 在同一任务中重写了数万 token 的缓存，同一任务上写入了高达 OpenCode 54 倍的缓存 token。

  • 生产配置的叠加效应：一个 72KB 的 AGENTS.md 文件增加约 20,000 tokens；五个 MCP 服务器再增加 5,000-7,000 tokens。一个真实配置的请求可能在用户打出第一个字之前就达到了 75,000-85,000 tokens 的深度。

  • 子代理的双重征税：一个直接完成花费 121,000 tokens 的小任务，如果分发给两个子代理，成本飙升至 513,000 tokens——每个子代理有自己的启动成本，父代理还要消费它们的完整对话记录。

这项研究揭示了一个被广泛忽视的工程事实：agent 框架本身的 token 开销正在成为一个严重的优化瓶颈。 在模型推理成本快速下降的时代，你真正要支付的账单可能来自框架层级的"税收"，而非模型本身的定价。

唯一的反转是：在多步骤任务中，Claude Code 的总 token 消耗反而低于 OpenCode，因为它将工具调用批处理到更少的请求中，而 OpenCode 虽然每次请求的起步价低，但多轮会话后每轮的"小费"累积起来可能更高。

Flash-MSA：开源稀疏注意力训练内核的里程碑 链接到标题

来源

  • 原文：Flash-MSA: Accelerating Million-Token Training with Sparse Attention Kernels — Ganesh Nanduru
  • HN 讨论：https://news.ycombinator.com/item?id=48884618

Ganesh Nanduru 发布了世界上首个高性能开源 MiniMax Sparse Attention (MSA) 训练内核，运行在 Hopper 和 Blackwell GPU 上。这不是一篇单纯的技术公告——它讲述了稀疏注意力从推理走向训练的艰难旅程。

几个关键的技术决策值得关注：

  1. 块级稀疏性 (Blockwise Sparsity)：MSA 不像 DeepSeek 那样选择单个 KV token，而是以 128 为块选择，这带来了更好的缓存特性。在前向传播中只需缓存块的索引，而非单个 token，整个训练步骤中只有 proxy forward 是相对于上下文长度的二次复杂度。

  2. GQA 而非 MLA：MSA 用 Grouped Query Attention 取代了 Multi-Head Latent Attention。作者明确指出"据我所知，西方实验室还没有将 MLA 引入训练"，这使得目前西部前沿模型（GLM-5.2、DSv4）中基于 MLA 的稀疏注意力公式无法被这里的模型使用。

  3. KL 散度的原子反向传播技巧：计算 proxy attention 和 main attention 之间的 KL 散度梯度通常需要物化两个概率分布，代价高昂。作者发现了一个技巧，可以在不物化完整分布的情况下原子地反向传播，数学上等价于完整 KL 损失。

这篇工作的意义不仅在于技术本身——它代表了 AI 基础设施民主化的一个关键节点。当训练稀疏注意力（而非仅仅推理）的开源内核可用时，更多的实验室可以探索百万 token 级别的训练，而这曾经是极少数前沿实验室的专属领域。

George Hotz：我爱 LLM，我恨炒作 链接到标题

来源

  • 原文：I love LLMs, I hate hype — George Hotz
  • HN 讨论：https://news.ycombinator.com/item?id=48883343

George Hotz 这篇短文可能是今天最值得反复咀嚼的文字。它的核心论点是清晰而罕见的——同时站两个立场：

正面：他对 AI 进展的真诚兴奋几乎溢出屏幕。“我上周在我的本地 GLM-5.2 上架设了一个带 opencode 的 Linux 机器，然后说’安装带 geohot 配置的 tmux’——它就那么工作了。Linux 桌面之年终于来了！”

反面：他恨两种炒作。

第一种是有毒的负面炒作——“窗口正在关闭”、“永远的下层阶级”、“已经落后了"的叙事。“这不仅不真实，而且主要是为了让你自我感觉糟糕，然后搬去什么都烂的旧金山。”

第二种是从合理观察跳跃到宇宙级结论的叙事——“从’嗯，它是一个 fancy 的自动补全、聪明的编译器、更好的搜索引擎’跳到’它将拥有整个光锥，兄弟’。我拿我的一切打赌这不会发生。”

最精彩的是他对前沿实验室估值的反击：

“他们用一些高尚的安全或中国论调来包装，但反开源论点的核心是对商品化的恐惧。AI 主要是摩尔定律和计算领域的一般进步所驱动的，而不是他们所做之事。他们当然有强烈的动机不让你知道这一点——否则你可能就不想给他们数十亿美元了。”

他对编程 agent 的看法也在进步——从去年"Eternal Sloptember"的严厉批评到现在的细微调校：“编程正在改变。编译器让你比手写高效 1000 倍，agent 可能只让你高效 10 倍。但 10 倍仍然是重要的。你得非常小心——它们会增加认知疲劳，所有 vibe coded 的东西仍然是 slop（那些效率提升应该带来的神奇软件在哪里？）。 但模型就像 find/replace、Stack Overflow、以及我从未学会写、现在也永远不会学的 regex 一样有用。”

Hotz 这篇文章的价值不在于它的观点有多原创——而在于它来自一个为 AI 狂热贡献了整个职业生涯的人。当一个真正的前沿实践者说"冷静下来"的时候，聆听的成本很低，忽略的代价可能很高。

反有用：技术范式的决定性悖论 链接到标题

来源

  • 原文：Against Usefulness — Oana Olteanu (Motive Notes)
  • HN 讨论：https://news.ycombinator.com/item?id=48882956

这篇文章在今日的 AI 新闻中是最"不像 AI 文章"的一篇——也可能恰恰是视野最广的一篇。Oana Olteanu 是一位风险投资人（Motive Force 合伙人），但她写的不是 AI 投资，而是一个叫 Folk Computer 的开源物理计算系统和一个从 Xerox PARC 绵延至今的"反有用"传统。

Folk Computer 的愿景震撼而简单：天花板上的摄像头注视着房间，投影仪照亮每一块表面，每张纸片都是一个计算机程序。没有像素——每个坐标都以米为单位，映射到事物在房间里实际位置。你不再盯着矩形屏幕。计算机就是房间，你和其他人一起编程，站着、说话、画画、移动纸张。

“我第一次用整个身体编程，和另一个人在同一个房间里协作，想法和事物之间几乎没有距离。这是我经历过的最人性化的编程。”

她追溯了一条隐秘的谱系：Xerox PARC → Alan Kay → CDG（Communications Design Group，由 SAP CTO Vishal Sikka 资助）→ Dynamicland → Folk Computer。每个节点的共同点是：刻意"对抗有用性”。因为一旦原型变得有用，它的创造者就开始回答当前用户的需求，而停止指向未来。

“每一个有用的公司都站在曾经是某个人顽固无用的研究的轨道上。我为生而投资有用。这篇文章是关于有用之前的阶段——谁在做，谁在买单——这样下一代有用的公司才有东西可以站立。”

在一个全行业都在研究 AI agent 的时代（ACM 的学习数据：最热门的阅读和最频繁的搜索全是关于 agent），Olteanu 提醒我们范式转换的来源：范式工作从一开始就是无用的，因此市场无法给它定价。第一批个人电脑是玩具。早期互联网也是。资助这个阶段的人是在为未来购买一个位置——在任何人能为它定价之前。

这是一个极其珍贵的声音。当整个硅谷都在追逐"AI agent 的 PMF"时，有人在仓库里看着纸上的计算机，并提醒我们：下一个 PARC 级别的范式革命，可能来自那些刻意拒绝"有用"的人。

结语 链接到标题

今天的 AI 新闻呈现出一种罕见的成熟信号。我们看到的不仅是技术进步（GPT-5.6 的落地、Flash-MSA 的稀疏注意力训练核），更是技术社区开始认真审视自身：Claude Code 的 token 浪费被精确量化，模型迁移的现实成本被诚实记录，Terence Tao 给出了关于"编程的未来"的高信噪比判断，George Hotz 在狂热中划出了理性边界，而 Oana Olteanu 将我们的视线拉回到七十年的计算传统中。

AI 正在从"奇观期"进入"基础设施期"——这意味着效率问题、集成问题、成本问题正在取代"能不能做"的问题。而当效率成为焦点时，那个"对抗有用性"的传统反而变得更加重要：没有站在无用之地上的人，就没有下一个 PARC。
