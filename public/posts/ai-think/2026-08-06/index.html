二、Cloudflare OS：当企业 OS 被 agent-first 重写 链接到标题

Cloudflare 在 Agent Week 发布了可能是今天最具野心的产品——Cloudflare OS。它不是一个普通的企业软件，而是一个完全开源、agent-first 的操作系统，目标是把每个企业职员都变成一个"有 agent 加持的知识工作者"。

最引人注目的不是它所宣称的能力（文档生成、工作流自动化、应用搭建等），而是它的安全架构。Cloudflare 发现了代理时代的核心安全悖论：MCP（Model Context Protocol）解决了"agent 能调哪些工具"的问题，但没有解决"agent 看到的数据能被谁分享"的问题。他们的答案是 Gatekeepers——一种服务级别的 Worker，位于 Cloudflare OS 和外部系统之间，不仅控制 agent 能调什么 API，还追踪 agent 看到了什么资源，以及这些资源能流向哪里。

“MCP alone does not tell us which underlying resources an agent has observed. The agent can combine information across systems, send it somewhere less restricted… Authorization has to account for where the data can go next.”

这种"数据溯源"式的权限模型，可能是未来所有企业 AI 平台的标配。当 agent 不再是单次会话而是持久的、可共享的工作单元时，传统的 API key + OAuth 模型完全不够用。Cloudflare 用 Cap’n Web（object-capability RPC）和 Dynamic Worker 隔离，实现了每个 app 以最小权限运行的设计原则。

另一个值得关注的细节是：Cloudflare OS 提供了"蓝图"（blueprint）分享机制——你可以分享一个 app 的模板（不含数据、凭证、会话历史），他人可以基于它创建自己的版本并用 AI 修改。这本质上是把"低代码"升级成了"AI-native 应用复制"，比传统的 SaaS 应用市场更灵活地传递生产力。

三、4B 参数的逆袭：Castform + Neon 如何以 1% 的成本挑战 GPT-5.6 链接到标题

如果说今天是"价格战正式打响"的一天，那 Castform 和 Neon 的联合作战是最好的证据。他们把一个 4B 参数的开源模型经过 RL 后训练（post-training），在检索任务上实现了与 GPT-5.6 Sol 相当的准确度，成本却只有后者的百分之一。

关键在于两个洞察。第一，RL 后训练正在变成新的大模型优化范式：原始模型的能力不足，但通过强化学习在特定任务上的 trial-and-error 循环，可以显著弥补差距。Castform 做的就是把"后训练"从需要 ML 专家的复杂流程，变成像 prompt engineering 一样可操作的工具。

“Most teams’ best training data is just sitting in their databases. The problem is that turning raw data into something usable is hard… Pointing Castform at Neon skips both.” — Ying Hang Seah, Castform 联合创始人

第二，向量搜索的时代正在让位给 agentic retrieval。2022 年的 RAG 是 embedding 相似度搜索的一锤子买卖；2025 年开始，agent 在做的是多跳搜索——将大问题分解为小问题，每步调用一次搜索工具。这意味着每轮对话的 token 消耗和延迟都成倍增加。Castform 的策略正好在这里切入：用一个后训练过的小模型替代每次调用的前沿模型，用 Neon 的 Lakebase Search 作为高速检索后端。

这一组合的意义不止于省钱。它暗示了一个新的分工模型：前端用轻量、后训练的专用模型处理 95% 的流量，只在最复杂的边缘情况回退到 GPT-5.6 这类顶级模型。这比单纯地"等模型降价"要聪明得多——因为模型成本下降的速度，赶不上 agent 调用次数增长的速度。

四、Prime Agent：当 agent 可以自我改进 链接到标题

Prime Intellect 发布的 Prime Agent 在 ARC-AGI-3 上达到了 95.5%（超越人类专家基线），但比这个数字更有趣的是它的架构理念。

核心是两个抽象：递归语言模型（RLM） 和 持续框架（Continual Harness）。RLM 把上下文当作变量、把子 agent 委托当作 REPL 中的函数调用——这意味着 agent 可以编程式地访问自己的历史、子 agent 和工具。持续框架更进一步：它允许 agent 对自己的 prompt、技能、记忆和子 agent 进行 CRUD 操作。这使得 agent 可以在运行中学习、调整自己的行为，而不是固定在初始设计中。

“Static, hand-engineered sub-agents, prompts, skills, and memory are set once at design time and never adapt to what the agent learns while running.”

这种"自修改"能力，结合 agent-to-agent 通信机制，打开了新的可能性：一个 agent 可以 spawn 持久子 agent、在后续轨迹中向它们发送消息、甚至与其他 Prime Agent 会话直接通信。整个系统更像是一个 agent 集群而非单一助手。

从实用角度看，Prime Agent 的设计还解决了 agent 系统一个被低估的问题——上下文管理。通过异步压缩和 IPython kernel 的垃圾回收，它避免了长会话中内存的无限制膨胀。这些工程细节往往比漂亮的架构图更重要。

五、Agent 生态的百花齐放：从生产调试到数字绘画 链接到标题

今天的新闻还展示了 agent 应用场景的巨大跨度。

HyperProbe（YC S26）解决的是一个非常具体的痛点：生产环境的只读调试。它让 coding agent 在运行时放置虚拟断点，捕获变量状态，无需重新部署或重启服务。这本质上是把传统的"调试器"变成了 agent 的传感器。“3到4小时 → 少于10分钟"的根因分析时间数据，说明即使是在最务实的生产运维领域，agent 也在从一个"辅助工具"变成"主要执行者”。

另外两篇技术文章——Building an Advanced Agentic Harness 和 Painting with Gaussians——虽然技术深度不同，但共同指向一个趋势：AI 工具的建造门槛正在从"能跑模型"转向"能设计好 agent 的调用的架构"。Painting with Gaussians 的作者用 2D Gaussian splat 模拟油画笔触，结合 Perlin 噪声、小波变换和结构张量，做出了一款交互式数字绘画工具。这是传统计算机图形学在 AI 时代的再发现——当生成式模型垄断了注意力时，把经典算法和现代 agent 工作流结合起来，反而可能产生惊喜。
